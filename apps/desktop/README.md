# OpenAdab Desktop

The OpenAdab desktop app gives fiction writers and AI assistants a visual
workbench for schema-driven chapter drafting, wiki management, and context
packing. It wraps the `openadab` CLI in an Electron shell, keeping the CLI
as the authoritative workflow engine while adding a rich graphical
interface.

## Getting Started

### Prerequisites

- [OpenAdab CLI](https://github.com/YBY/openadab) installed (`openadab` must be in your PATH).
- An existing OpenAdab project, or the ability to create one.

### Opening a Project

1. Launch the OpenAdab desktop app.
2. From the welcome screen, click **Open Project** and select your project
   directory. The app detects OpenAdab projects by the presence of
   `adab/config.yaml`.
3. Alternatively, pick a project from the recent projects list.
4. The app loads the project root, reads `adab/config.yaml`, and displays the
   project dashboard.

### Creating a New Project

Use the CLI to initialize a project, then open it in the desktop app:

```bash
mkdir my-novel && cd my-novel
openadab init --schema chapter-draft
```

Then open `my-novel/` in the desktop app via **Open Project**.

## Feature Tour

The app has seven route tabs accessible from the left sidebar:

### 1. Project

Dashboard overview of the current project. Shows:
- Project title, language, active schema, and host adapter.
- Recent changes and their status (blocked, ready, done).
- Quick actions to create a new change or view the log.

### 2. Manuscript

Browse and edit manuscript chapters. Shows the manuscript file tree under
`adab/manuscript/`. Click a chapter to open it in the editor. Changes are
saved directly to disk and validated through the CLI on refresh.

### 3. Changes (Primary Workbench)

The core workflow view. Each change is an artifact DAG (directed acyclic
graph) showing artifacts and their dependencies:

- **Artifact nodes** display their state: blocked, ready, in progress, or
  done. Click any artifact to open its editor.
- **Instructions** load with the `instructions` CLI command. Each artifact
  has generation instructions and dependency context.
- **Context Pack** assembles relevant wiki pages and manuscript chapters
  for context. View token counts, buckets (must-read, optional, excluded),
  and pin/unpin items.
- **Validation** runs mechanical checks (file existence, frontmatter,
  schema conformance) and semantic review prompts. Issues appear in the
  Inspector panel.
- **Status** refreshes automatically after saves, showing artifact
  completion and manifest health.

### 4. Timeline

Explorer view showing a chronological progression of changes, mentions, and
wiki updates. Each event links to its source evidence in the manuscript or
wiki. Stale index warnings appear when the index needs regeneration.

### 5. Wiki

Browse, search, and edit the living wiki. The wiki contains your
characters, locations, plot threads, and world rules as Markdown files with
YAML frontmatter.

- **Wiki index** shows a table of contents generated by `openadab wiki
  index`.
- **Wiki diff** previews changes a chapter draft would make to the wiki
  before applying them. Review operations individually: each shows the
  target page, old value, new value, evidence, and risk level.
- **Apply diff** can be done as a dry run (preview only) or a full apply,
  after explicit user approval for each canon-mutating operation.

### 6. Schemas

View available schemas, their artifact definitions, dependency rules,
templates, and validation rules. Fork a built-in schema to create a custom
workflow, or validate a schema directory.

### 7. Agent Dock

Optional AI assistant workspace. Configure an ACP-compatible agent (e.g.,
OpenCode) to assist with writing, reviewing, and wiki maintenance.

- **Configure** your agent from the Agent Dock settings panel. Choose a
  preset (OpenCode default) or provide a custom command and arguments.
- **Start a session** to spawn the agent process. Messages appear in a chat
  panel.
- **Permission prompts** appear as modals when the agent requests access to
  project files, CLI commands, or canon-mutating operations. Approve or
  deny each request with a preview of what the agent wants to do.
- **Session logs** are persisted to `adab/agent-log.jsonl` for audit.

The Agent Dock is a side tool. The core workflow works without any agent
configured.

## Panels and Inspector

### Inspector

The right-side Inspector panel shows contextual detail for the selected
artifact or change:

- **Context Pack card** — what wiki pages and chapters are included in the
  current artifact's context, with token counts and buckets.
- **Validation card** — mechanical check results and semantic review
  prompts.
- **Wiki Impact card** — changes this artifact would make to the wiki, with
  risk levels.

### Transcript

The bottom Transcript panel shows a chronological log of all CLI commands
executed during the session. Filter by initiator (user, agent,
auto-refresh) to reduce noise. Click any entry to see full stdout/stderr
and parsed JSON output.

### Keyboard Shortcuts

| Shortcut | Action |
|----------|--------|
| `Ctrl+O` | Open project |
| `Ctrl+S` | Save current file |
| `Ctrl+Shift+P` | Command palette |
| `Ctrl+1..7` | Switch to route tab |
| `Escape` | Close modal / dismiss prompt |

## Architecture at a Glance

The app runs as three processes:

1. **Main process** (Node.js) — BrowserWindow, CLI child process management,
   filesystem I/O with path guards, agent supervision, transcript
   persistence.
2. **Preload** (isolated world) — narrow typed IPC bridge via
   `contextBridge`. Exposes `window.openadab` API to the renderer.
3. **Renderer** (Chromium) — React UI. Has no Node.js or filesystem access.
   All data flows through typed IPC channels.

The `openadab` CLI runs as a separate child process. The GUI never directly
manipulates project files for workflow state — it always delegates to the
CLI.

For detailed architecture, security model, and data flow, see
[docs/architecture.md](docs/architecture.md).
